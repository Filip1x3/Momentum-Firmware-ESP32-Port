# Bug fixes under validation — 2026-10-23

These changes address reported application resets, slow menu entry and beacon
formatting. Normal and Dual Boot builds both pass. At the user's subsequent
request, the Dual Boot Momentum image was flashed locally on 2026-10-23;
nothing has been published. Host tests do not guarantee zero resets or
establish an on-device loading-time improvement.

## Changes

- **Caesar Cipher / Bomberduck:** initialization, mutex ownership, GUI/input
  callback lifetime and cleanup fixes; bounded game state. These are external
  FAP applications, so installing firmware alone does not replace their code.
- **ProtoPirate Receive:** receive/history lifetime and synchronization fixes.
  **Updated FAPs and matching firmware are both required** for ProtoPirate,
  Caesar Cipher and Bomberduck. Use ESP32-port packages, not stock Flipper FAPs.
- **NFC Read / result parsing:** parser filenames are cached without mapping
  all plugin ELFs first; protocol/features are discovered on demand. The earlier
  deferred-parser changes in Read/Detect remain in place.
- **IR Universal Remotes, including TVs:** opening builds a buffered
  name/offset index rather than decoding every signal body. The selected
  signal is still decoded and validated before transmission. See
  [NFC_IR_STARTUP.md](NFC_IR_STARTUP.md) for compatibility and validation limits.
- **Built-in Bluetooth module / BLE HAL:** partial-start failures use
  state-aware cleanup, and restoring the normal Bluetooth service respects the
  user's **Bluetooth Off** setting. This is the module identified in the bug
  report. The same controller leak and partial-initialization handling are fixed
  in the Walk/scanner lifecycle; scan/read/write operations are unchanged.
  The separate SD BLE FAP is unchanged and was not requested for this fix.
- **Funny SSID:** beacon information-element lengths and buffer bounds are
  checked, and the transmitted length follows the serialized frame length.
  Validation is in memory only, without RF transmission.
- **125 kHz RFID:** an NFC reader is not a 125 kHz RFID reader. The T-Embed's
  onboard NFC hardware does not provide the external 125 kHz analog hardware
  needed for this feature. Do not claim standalone 125 kHz support or confuse
  an NFC read test with an RFID test.

## Validation performed

Native fake-platform tests exercise application lifecycle/input ordering,
mutex cleanup, bounded game state and ProtoPirate receive/history ownership.
NFC/IR tests exercise lazy parser dispatch, index rebuilding, exact offsets,
and error paths that must reject a signal before transmission. Beacon tests
exercise TLV lengths, buffer capacity and malformed input entirely in memory.

Passed validation:

- **22 Python checks**, plus **4 beacon serialization tests** without RF.
- **2,000 Caesar/Bomberduck application lifecycles** and **66,000 idle ticks**.
- **1,000 BLE lifecycle cycles**, including **5 initialization-failure cases**
  and **4 cleanup-failure cases**.
- **1,000 BLE Walk lifecycle cycles**, **7 initialization-failure cases**,
  asynchronous-registration timeout and **4 cleanup-failure cases**. Already
  started calls remain idempotent; GATT teardown checks that the host is live.
- **1,000 IR index rebuilds**, plus NFC lazy-parser and IR signal-validation checks.
- **100,000 concurrent ProtoPirate history operations** and **20,000 teardown
  cycles**.
- **SD archive validation:** exactly three FAPs plus their `Manifest` and
  `files.txt` records updated; all **3,107** other records retain identical
  uncompressed and compressed bytes. CRC validation passes. Asset packs,
  existing BLE FAP and `sdcard-package.json` are unchanged.

These tests do not certify physical compatibility or Bluetooth coexistence.

Final local firmware verification:

- Normal image: **3,644,864 bytes**, build and partition-size check pass.
- Dual Boot image: **3,656,912 bytes**, build and partition-size check pass.
- Both images link all **11** newly changed built-in source objects and retain
  the **10** earlier startup-fix source objects. Both retain two usable FreeRTOS
  TLS slots. The Dual Boot worker's internal-memory placement, stack and TCB ABI
  checks pass; the Normal image has no paired worker buffers.
- The firmware API table's **1,181** hashes remain strictly sorted.
- Local `sdcard.zip`: **12,771,193 bytes**, CRC and exact-entry verification pass.

The reviewed Dual Boot Momentum image was written only to its application slot
at `0x10000` and verified against the local image by the device's flash digest.
The installed partition table matches the reviewed layout; the boot selector
is byte-identical before/after, with Momentum selected. Bruce, bootloader,
partition table, NVS and SD were not written. A local rollback copy of the old
Momentum application slot was saved before flashing. Passive serial observation
after reset produced no output, so it does not establish interactive stability.
Normal firmware was built but not flashed. The three updated SD FAPs still need
to be installed; physical functional tests remain pending.

## Manual hardware checklist

After an explicit installation is requested, test on a T-Embed CC1101 using the
matching updated SD FAPs:

- Open/exit **Caesar Cipher** repeatedly; submit short and maximum-length text.
- Open/play/exit **Bomberduck**; include idle periods and holding Back to exit.
- Open/exit **ProtoPirate Receive** repeatedly and inspect receive history using
  only permitted signals; record any error/reset log.
- Check **NFC Read**, the first card result, retry and return to the next menu
  with known supported cards. Compare the same card and SD before/after.
- Open **IR → Universal Remotes → TVs**, return and reopen it. If testing a
  remote action, use only owned equipment and a known compatible signal.
- Open/exit the **built-in Bluetooth module** repeatedly, including startup
  failure recovery. Check that normal Bluetooth remains enabled or disabled
  according to its saved setting; record any reset logs.
- Check Funny SSID serialization with the in-memory tests. Any later RF check
  needs an authorized controlled environment; none was performed here.
- For **125 kHz RFID**, first verify that supported external reader/analog
  hardware is actually connected. An NFC tag/read test is not an RFID test.
- Regression-check SD applications and Settings with Wi-Fi/Bluetooth on and
  off. For Dual Boot, also verify switching to Bruce and back without replacing
  protected settings or keys. Do not mix Normal and Dual Boot partition files.

Samsung Watch and Evil Portal were marked working in the report, not newly
verified here. This validation makes no change to RF power, timing or rate.
