# Settings, web flasher and stable Bruce — 2026-10-27

## Settings

Removed the **Update Firmware** shortcut from **Settings → System** and removed
its deferred WLAN launch target. Others and qFlipper Settings retain their
indices. This does not remove the maintenance bootloader or USB update backend.
Normal and Dual Boot firmware both build successfully. The paired build was
subsequently installed at the user's request; see the installation record below.

## Web flasher

The reported `Unknown installed layout` message did not by itself identify a
root cause; no failing user's partition dump/log was supplied. The patch covers
two independently testable causes without removing the protection:

- USB flash reads are checked for exact length and compared against a separate
  on-device MD5. A failed read retries once; persistent failure reports a USB
  read error, not a recommendation to switch to first installation.
- The stub's read trailer is drained before a following serial command.
- Two exact older single-app layouts shipped by this port are recognized for
  complete-package migration. Matching NVS/PHY locations, a valid table checksum
  and a Momentum ESP32 app descriptor are required before any write.
- Equivalent reordered current partition tables are compared semantically;
  ordinary OTA still writes only the inactive slot and one activation sector.
- Unknown, corrupt, encrypted and differently located partitions remain blocked.
  Raw BINs cannot migrate a legacy layout or overwrite a Dual Boot companion.

Protected regions remain in browser memory only, are never uploaded/logged and
are checked after installation. No whole-chip erase or SD formatting was added.
The legacy migration is not power-loss-atomic and its confirmation warns about
backup and possible USB recovery.

The code-only fix was deployed to the existing Cloudflare project
`momentum-esp32-port`. The production root serves the new script. Existing public
firmware downloads, the fallback catalog and GitHub releases were not replaced.
Private website repository visibility was not changed. Local packaging helpers
now optionally write to a new explicit output directory without touching public
downloads, allowing the new firmware to be tested before release.

## Stable Bruce

The old companion's source base was release 1.16, but the default upstream
`BRUCE_VERSION` flag displayed `dev`. The new source is based on actual stable
release **1.16.1**, commit `ba519c936c87b89c9c667c15b932d7faca5360d5`, not merely a
renamed development build. UI version is `1.16.1`, and the isolated descriptor
is `bruce_mntm_db1` / `1.16.1-db1`.

The previous modified tree was preserved. The new tree retains Momentum's
return menu/logo, `/bruce` SD confinement, separate NVS, protected partition
write wrappers and standalone-upload/factory-image guards. No radio operations
were performed. The complete corresponding source archive and GPL-3.0 license
are stored under `third_party/bruce-dualboot/`; the historical source is retained.

## Validation and limits

- 23 firmware source/wiring regressions pass.
- 28 bundle/source-pin tests and the private-data source-export checks pass.
- 56 web-flasher tests pass; production build and Cloudflare Functions bundle
  compile. Cases cover retries, no-write failures, both legacy migrations,
  reordered layouts, hashes, protected settings and boot-selector ordering.
- Stable Bruce builds successfully. Eight Python guard/version tests plus native
  NVS protection, SD path validation and logo tests pass without hardware.
- Both Momentum profiles retain two TLS slots and the paired worker's internal
  RAM placement/ABI. Current objects and image hashes are checked after linking.
- The segmented bundle validates both partition tables, all app descriptors and
  image checksums, linked NVS/flash wrappers and non-overlapping write ranges.
- Source archive CRC and all recorded source hashes pass verification.

These checks are not a full firmware/security audit and do not establish that
every upstream Bruce feature is bug-free. Existing third-party compiler warnings
remain, including audio-decoder bounds diagnostics. Physical startup, display,
SD and both-direction switching tests are pending for the new stable companion.
No firmware GitHub release was published and no M5Stick S3 port was started.
